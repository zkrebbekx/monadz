# Go 1.27 generic methods: what monadz learned

Go 1.27 lets a method declare its own type parameters:

```go
func (o Option[T]) Map[U any](f func(T) U) Option[U]
```

This is the feature that makes monadz possible. This page lists the limits
that we found while we built monadz. We checked each error text with the
Go 1.27.1 compiler.

## 1. Interface methods cannot have type parameters

This does not compile:

```go
type Monad[T any] interface {
	AndThen[U any](func(T) Monad[U]) Monad[U]
}
```

```text
./main.go:4:9: interface method must have no type parameters
```

**Effect:** Go has no `Functor` or `Monad` interface. You cannot write one
function that accepts every monad. Each monadz type has its own methods with
the same names, so the API feels the same across types.

## 2. A method cannot grow its own type ("instantiation cycle")

This does not compile:

```go
func (o Option[T]) Zip[U any](other Option[U]) Option[Pair[T, U]] {
	return Option[Pair[T, U]]{}
}
```

```text
./main.go:8:13: instantiation cycle:
	./main.go:13:55: T instantiated as Pair[T, U]
```

The compiler must be able to list every instantiation of `Option`. `Zip`
makes `Option[Pair[T, U]]`. That type has a `Zip` that makes
`Option[Pair[Pair[T, U], V]]`, and the list never ends.

This rule is not new. It dates from Go 1.18 and applies to every method of a
generic type, generic or not. This non-generic method also fails, on every
release from Go 1.22 to Go 1.27:

```go
func (o Option[T]) ToSlice() Option[[]T] {
	return Option[[]T]{}
}
```

```text
./main.go:3:13: instantiation cycle:
	./main.go:8:37: T instantiated as []T
```

Generic methods do not change the rule. They only make you meet it more
often, because a method like `Zip` is now possible to write.

**Effect:** `Zip` is a function in each helper package (`options.Zip`,
`results.Zip`, `tasks.Zip`). The `ZipWith(other, f)` methods are allowed,
because their result type `V` is a new type parameter, not a type built from
`T`.

## 3. A receiver must name its type parameters

`Flatten` and `Transpose` are functions for a different reason. Their input
is `Option[Option[T]]`, and a receiver cannot have that shape:

```go
func (o Option[Option[T]]) Flatten() Option[T] {
	return o.v
}
```

```text
./main.go:8:16: receiver type parameter Option[T] must be an identifier
```

**Effect:** `options.Flatten`, `options.Transpose`, `results.Flatten`,
`results.Transpose`, and `eithers.Flatten` are functions.

## 4. You cannot add methods to another package's type

This rule did not change in Go 1.27. A library like `samber/mo` must add the
methods itself. Your code can only wrap its types.

## 5. Old tools reject generic methods

A `gofmt`, `gopls`, `staticcheck`, or `golangci-lint` binary that was built
with Go 1.26 or older fails with `method must have no type parameters`.

**Fix:** Run `go fmt` and `go vet` from the Go 1.27 toolchain. Rebuild your
editor and lint tools with Go 1.27.
